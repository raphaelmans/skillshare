# Report delivery state and share the worktree

An Implementation Run ends with a closing report that states tasks verified, whether screens were seen rendered against Paper, commit and push state, and where each migration has been applied, leading with the risk when dependent code is pushed ahead of its migration. It leaves other sessions' uncommitted work in place, commits only its own files, ticks tasks as they are verified so a cut-off session can resume, and reverifies delegated work itself. Read-only `status` and `help` slices report where a change stands and how to invoke the skill. Observed runs ended with passing tests but no rendered review, a pushed change whose migration existed only locally, and a pause waiting on a parallel session that the user then overrode.
