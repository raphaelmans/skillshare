# Stay agnostic to planning format

The skill was built on OpenSpec, requiring a 4/4 artifact set (proposal, delta specs, design, tasks), the OpenSpec CLI for validation, and a root `openspec/` directory for the manifest. As the repositories it serves retire OpenSpec, it is renamed from `paper-openspec` to `paper-design` and reads a Change's intent from a Change Source in whatever format the repository uses: specification documents, product requirements, plans, or tracker issues. Content is identified by Source Role (Intent, Requirements, Decisions, Tasks) rather than by file, and a Change Source is Planning-Ready when Intent and Requirements are specific enough to scope; Tasks are required only before `implement`, and a missing task list is proposed from the requirements and approved before it is recorded. The repository's Planning Convention (where changes live, how they are identified, closed, and validated) is observed from the Paper Manifest, repository instructions, established examples, or the user's message; it is never imposed, and the skill never installs a planning tool. `init` records the observed convention in an optional `PAPER.md` section that stays within schema v1, and the Manifest Root becomes the Git root or a self-contained nested project instead of the directory holding `openspec/`. Every Paper-side rule and approval gate from ADRs 0001–0013 is unchanged. Only the source of intent is generalized, and where those ADRs name OpenSpec they now read as the Change Source.
